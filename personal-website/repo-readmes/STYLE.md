# Repository README style

Write for an engineer inspecting the code. Use first person for personal decisions and "we" for shared work. Credit agents and human review separately. Short sentences, concrete constraints, no hype, badges, contribution cards or invented impact numbers.

Use the TEMPLATE headings in order, including in short archive-project drafts. Link back to the matching site page; the website repository links to the homepage. A site archive entry does not mean the GitHub repository is archived.

Commands must be supported by inspected source or documentation. Distinguish "documented upstream" from "executed successfully here". Missing setup, tests, team details and outcomes stay explicitly unverified. Do not promote a planned endpoint into a working demo. Do not copy secrets, private hostnames, client identities or client repository associations.

The kit contains five tier-1 drafts and eight tier-2 drafts. One originally proposed project is withheld pending explicit public clearance. There is no replacement pin. Keeper stays described-only until its publication audit and separate visibility approval.

Evidence was inspected read-only on 2026-10-19: upstream READMEs for the public projects, the newer Volta app's package scripts, the NASA frontend package scripts, and repository listings for the older harness and voice coach. Their READMEs returned 404. Keeper facts come from the approved site registry; no private source is reproduced. External commands have not been executed here. Recheck upstream instructions before publishing each draft.
