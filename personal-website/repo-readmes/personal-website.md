# Personal website

## What

My website, as a small game. You walk around my cabin in Nova Scotia and find my work in the place: the résumé on the table, past projects in boxes on the workbench, and questions you can ask me at the fire. A bar in the corner goes straight to my work, my résumé and my contact details.

## Why

My last redesign was generated by a coding agent with almost no input from me, and I rejected it. This time I decided the place, the story, each interaction and each line, and the agent built it.

## Run it

The Next.js app is in the nested `personal-website/` directory. Use Node 24 and pnpm 9, and run these from that directory:

```sh
pnpm install
pnpm dev
```

Open localhost:3000.

## How it's tested

```sh
pnpm test
pnpm lint
pnpm type-check
pnpm build
```

The tests run the game's simulation directly: pathfinding to every spot the game walks a guest to, the dog's fetch, the fishing rules and where split wood lands. They check that HUGO's prepared answers never speak as me, that the résumé source and the GitHub profile match a fresh render from the facts file, and that no client name appears in a tracked file. Client names are read from a gitignored list or the `HIDDEN_TERMS` secret, which CI requires.

## How it works

Next.js and React Three Fiber draw the scene. The pixel look comes from rendering at low resolution and scaling up, with toon shading and an outline pass. The world is a simulation in plain TypeScript with no 3D code in it, so ordinary tests can run it. Python scripts in `art/cabin/` build every model in Blender.

`src/content/profile.ts` holds the facts. `pnpm resume` builds the résumé PDF from it (it needs a local TeX install), and `pnpm readme` writes my GitHub profile README to `profile-readme/README.md`. Each headline number says how it was counted.

HUGO, the guide, only gives answers written ahead of time. A small model in the visitor's browser picks which one fits a typed question, and a keyword match does the same job where the model can't run.
